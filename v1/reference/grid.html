Grid, loops and boundary conditions ​

WaterLily works on a uniform Cartesian grid with one layer of ghost cells on every face. Scalars such as the pressure live at cell centres and are indexed p[I]; vectors such as the velocity live on cell faces and are indexed u[I, i], where u[I, i] is the i-component on the lower face of cell I in direction i. loc gives the physical position of either, and inside gives the range of real (non-ghost) cells.

Everything in the solver is written with @loop and @inside, which expand to KernelAbstractions kernels. That is what makes the same source run serially, multi-threaded, or on a GPU. Write your own metrics and body functions the same way and they will too.

BC! applies the domain boundary conditions each stage: a Dirichlet condition on the normal velocity and a Neumann condition on the tangential components, with periodic directions and a convective exit handled by perBC! and exitBC!.

Loop macros ​

WaterLily.@inside Macro
julia
@inside <expr>

Simple macro to automate efficient loops over cells excluding ghosts. For example,

julia
@inside p[I] = sum(loc(0,I))

becomes

julia
@loop p[I] = sum(loc(0,I)) over I ∈ inside(p)

See @loop.

source
WaterLily.@loop Macro
julia
@loop <expr> over <I ∈ R>

Macro to automate fast loops using @simd when running in serial, or KernelAbstractions when running multi-threaded CPU or GPU.

For example

julia
@loop a[I,i] += sum(loc(i,I)) over I ∈ R

becomes

julia
@inbounds @simd for J ∈ CartesianIndices(R)
    I = R[J]
    @fastmath @inbounds a[I,i] += sum(loc(i,I))
end

on serial execution, or

julia
@kernel function kern(a,i,R)
    I = R[@index(Global,Cartesian)]
    @fastmath @inbounds a[I,i] += sum(loc(i,I))
end
kern(get_backend(a),workgroup(get_backend(a))...)(a,i,R,ndrange=size(R))

when multi-threading on CPU or using CuArrays, with the workgroup size of workgroup. Note that get_backend is used on the first variable in expr (a in this example).

R is any array, such as a CartesianIndices, a face or a vector on the same device as a, and I takes its values.

Boundary conditions ​

WaterLily.BC! Function
julia
BC!(a,U,saveexit=false,perdir=(),t=0)

Apply boundary conditions to the ghost cells of a vector field. A Dirichlet condition a[I,i]=U[i] is applied to the vector component normal to the domain boundary. For example aₓ(x)=Uₓ ∀ x ∈ minmax(X). A zero Neumann condition is applied to the tangential components. saveexit=true leaves the normal component on the x exit face (upper x boundary) untouched, so a convective outflow set by exitBC! is kept and every other face is always overwritten. perdir lists the dimensions using periodic BCs instead. t is passed to U when it is a function (i,x,t)->....

source
WaterLily.exitBC! Method
julia
exitBC!(u,u⁰,Δt)

Apply a 1D convection scheme to fill the ghost cell on the exit of the domain.

Backends ​

The kernel launch configuration, and arrays allocated on the backend of a simulation.

WaterLily.workgroup Method
julia
workgroup(backend)

Workgroup size of the @loop kernels: 64 work-items on GPUs and on the CPU with KA 0.9. On KA 0.10 the PoCL CPU backend chooses the shape itself.

Arrays of zeros or ones of type T and size dims on the KA backend b, filled by KA with the KA backend or serially with the SIMD backend.
